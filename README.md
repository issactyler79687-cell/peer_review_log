# Peer Review Log

Peer Review Log is a Stellar Testnet dApp for recording transparent academic peer-review evidence through a Soroban smart contract.

A reviewer connects a supported Stellar wallet, enters a paper ID, score, and written review, then signs a transaction. The frontend calculates a SHA-256 hash of the review text and stores only that 32-byte evidence hash on-chain.

## Level 2 implementation

This repository includes:

- A Soroban smart contract written in Rust
- Five meaningful contract functions
- Persistent review and paper aggregation state
- A typed `ReviewSubmitted` contract event
- A React and TypeScript frontend
- Multi-wallet support through StellarWalletsKit
- Typed contract bindings generated by Stellar CLI
- Live Testnet reads and signed write transactions
- Pending, success, and failed transaction states
- Validation, wallet, contract, and network error categories
- Testnet deployment and transaction evidence

## User flow

1. Connect Freighter, Albedo, or xBull.
2. Enter a positive Paper ID.
3. Enter an integer score from 0 to 100.
4. Write a review containing at least 10 characters.
5. The frontend calculates the SHA-256 content hash.
6. Confirm the Soroban transaction in the selected wallet.
7. The contract stores the review and publishes `ReviewSubmitted`.
8. The frontend refreshes total reviews and the paper snapshot.

## Smart contract interface

| Function | Type | Purpose |
| --- | --- | --- |
| `submit_review` | Write | Authenticates the reviewer and records a review |
| `get_review` | Read | Returns a review by review ID |
| `paper_snapshot` | Read | Returns count, score sum, and average for a paper |
| `has_reviewed` | Read | Checks whether an address reviewed a paper |
| `total_reviews` | Read | Returns the total number of reviews |

### Stored review

Each review contains:

~~~text
review_id
reviewer
paper_id
content_hash
score
~~~

The written review itself is not stored on-chain. Only its SHA-256 evidence hash is recorded.

### Contract event

A successful submission publishes:

~~~text
ReviewSubmitted
~~~

Event topics:

~~~text
paper_id
reviewer
~~~

Event data:

~~~text
review_id
content_hash
score
~~~

## Contract errors

| Code | Error | Meaning |
| --- | --- | --- |
| 1 | `InvalidPaperId` | Paper ID is zero |
| 2 | `InvalidScore` | Score is outside 0-100 |
| 3 | `DuplicateReview` | The same wallet already reviewed the paper |
| 4 | `ArithmeticOverflow` | A stored counter cannot be safely increased |

The frontend presents errors under four user-facing categories:

- `validation`
- `wallet`
- `contract`
- `network`

## Wallet support

The frontend uses StellarWalletsKit with these wallet modules:

- Freighter
- Albedo
- xBull

Wallet code is loaded dynamically when the user connects a wallet or signs a transaction.

Never enter a recovery phrase or secret key into this project.

## Transaction states

The frontend displays these transaction states:

- `idle`
- `pending`
- `success`
- `failed`

After a successful transaction, the application:

1. Displays the review ID.
2. Displays the transaction hash.
3. Displays the SHA-256 content hash.
4. Provides a Stellar Expert explorer link.
5. Refreshes `total_reviews`.
6. Refreshes the selected `paper_snapshot`.

## Security notes

- Reviewer authorization is enforced with `require_auth()`.
- Duplicate submissions by the same wallet and paper are rejected.
- Scores are validated in both the frontend and contract.
- Review text is hashed locally before submission.
- No secret key is stored in the repository.
- Production dependency checks report no high or critical vulnerabilities.
- Indirect wallet dependencies may still report low or moderate advisories.
